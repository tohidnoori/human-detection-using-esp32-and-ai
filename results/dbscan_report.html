بنچمارک و بهینه‌سازی DBSCAN روی ESP32-S3

این پروژه عملکرد الگوریتم DBSCAN سه‌بعدی را روی ESP32-S3 N16R8 بررسی می‌کند و از یک پیاده‌سازی پایه تا یک pipeline شبیه کاربرد واقعیِ سه‌سنسوره پیش می‌رود.

مشخصات کلی

  • MCU: ESP32-S3
  • فرکانس CPU: 240 MHz
  • CPU: دو هسته
  • Flash: 16 MB
  • PSRAM: 8 MB
  • Framework: Arduino
  • Build System: PlatformIO
  • داده: سه‌بعدی

۱. آزمایش Baseline Scaling

روند کار

در این مرحله DBSCAN به‌صورت brute-force اجرا شد. برای پیدا کردن همسایه‌های هر نقطه، کل dataset بررسی می‌شود. تعداد نقاط به‌صورت نمایی افزایش داده شد تا رفتار زمانی و حافظه مشخص شود. تعداد نقاط از 90 تا 23040 بررسی شد.

نتیجه نهایی

پیاده‌سازی پایه تقریباً دارای این پیچیدگی است:

Time   ≈ O(N²)
Memory ≈ O(N)

در N = 11520:

زمان اجرا ≈ 79.438 ثانیه
حافظه اصلی DBSCAN ≈ 225 KB
PSRAM آزاد ≈ 7.96 MB

بنابراین محدودیت نسخه پایه بیشتر محاسباتی است، نه کمبود حافظه. برای N = 23040 اجرای کامل نهایی گزارش نشد.

۲. آزمایش Epsilon Sensitivity

روند کار

با ثابت نگه داشتن تعداد نقاط، ابعاد و MinPts، مقدار epsilon تغییر داده شد تا اثر شعاع همسایگی روی تعداد clusterها، نویز و زمان اجرا مشخص شود. 

N = 1440
Dimensions = 3
MinPts = 5
ε = 0.10 تا 1.50

نتیجه نهایی

  • در ε = 0.10 سه نقطه noise شدند.
  • از ε ≥ 0.20 در dataset آزمایش noise اصلی از بین رفت.
  • زمان اجرا فقط مقدار محدودی تغییر کرد.
  • در brute-force، تغییر epsilon تعداد scanهای کلی را خیلی تغییر نمی‌دهد.

نتیجه: epsilon بیشتر روی رفتار clustering اثر دارد تا روی حافظه و زمان نسخه brute-force.

۳. آزمایش MinPts Sensitivity

N = 1440
ε = 0.20
MinPts = 2, 5, 10, 20, 50, 100, 200
  • MinPts = 2: بیش از حد permissive بود.
  • MinPts = 5: بهترین رفتار را در dataset آزمایش ایجاد کرد.
  • MinPts = 10: باعث fragmentation شد.
  • MinPts = 20: بیشتر نقاط noise شدند.
  • MinPts ≥ 50: تمام نقاط noise شدند.

نتیجه: MinPts مستقیماً سخت‌گیری density را کنترل می‌کند.

۴. آزمایش Density Sensitivity

Dense   → radius = 0.25
Medium  → radius = 0.60
Sparse  → radius = 1.20
  • Dense بیشترین cluster expansion و بیشترین زمان را داشت.
  • Medium رفتار میانی داشت.
  • Sparse به دلیل کم بودن نقاط core، بسیار سریع‌تر شد.

نتیجه: تراکم داده روی زمان واقعی اجرا اثر زیادی دارد.

نتیجه اصلی پروژه

روی ESP32-S3، بهینه‌سازی الگوریتمی جستجوی همسایه بسیار مهم‌تر از parallelization ساده است. Spatial Grid بزرگ‌ترین بهبود را ایجاد می‌کند (21.48×) و Dual-Core زمانی مفید است که روی بخش محاسباتی مناسب، مانند cluster expansion، اعمال شود. در pipeline چندسنسوره شبیه‌سازی‌شده، سیستم فعلی در نرخ 10 FPS حداقل 660 نقطه در هر frame را به‌صورت real-time و با تشخیص پایدار دو انسان پردازش می‌کند.

محدودیت فعلی

آزمایش Real-Time هنوز با داده‌های سنسوری شبیه‌سازی‌شده انجام شده است و دریافت فیزیکی سه آنتن واقعی، baud rate، packet format، buffering و overhead واقعی UART هنوز وارد benchmark نشده‌اند. بنابراین عدد 6600 point/s یک نتیجه تجربی برای pipeline شبیه‌سازی‌شده فعلی است، نه سقف نظری نهایی ESP32-S3.
